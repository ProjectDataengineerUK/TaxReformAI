## Summary

Contorno pedido diretamente pelo usuário para o bloqueio real documentado em
`LLM_REAL_VERTEX_AI/SHIPPED_2026-08-03.md`: `taxreformai-dev` tem quota zero/mínima do Vertex AI
para modelos Claude (`429 RESOURCE_EXHAUSTED`, sem previsão de resolução, ação externa do usuário
no Console do GCP). Em vez de esperar, `orquestracao/llm/cliente.py` ganhou um segundo cliente
real, `ClienteAnthropicDireto`, implementando o mesmo `Protocol` `ClienteLLM` de sempre, mas
falando com `api.anthropic.com` diretamente — sem GCP, sem Vertex, sem a quota bloqueada.

Os dois clientes convivem, selecionáveis por `LLM_PROVIDER` (default `"direto"`, opção
`"vertex"`) — decisão explícita do usuário no `/brainstorm`, não uma substituição. Zero linha
tocada em `orquestracao/nos/` e zero dependência Python nova (`anthropic[vertex]`, já instalada,
inclui tanto `AnthropicVertex` quanto `Anthropic`).

## Lessons Learned

### Process

- Validar a assunção de dependência (A-001 do DEFINE) com um `pip install --target` real e um
  import de verdade, ainda no `/design`, evitou descobrir só no `/build` que `anthropic.Anthropic`
  precisaria de instalação separada — não precisou.
- Ler o código real dos NÓS (não só o `Protocol`) durante o `/design` revelou um conflito real que
  o `/brainstorm`/`/define` não tinham antecipado: os nós hardcodeiam `MODELO_HAIKU`/`MODELO_SONNET`
  no formato Vertex e passam isso direto pro cliente — sem uma tradução dentro do cliente
  concreto, a constraint "zero mudança nos nós" e "suportar dois formatos de ID" seriam
  incompatíveis.

### Technical

- Duas implementações reais e não-hipotéticas do mesmo trecho de código (extração de bloco de
  texto da resposta) já eram motivo suficiente para extrair um helper — sem virar abstração
  prematura, porque as DUAS já existiam de verdade antes da extração.
- Tornar `GCP_PROJECT_ID` condicional (só exigido com `LLM_PROVIDER=vertex`) evitou uma barreira
  artificial para o caminho novo, sem afetar produção (onde a variável já é injetada
  incondicionalmente por outros motivos, ex. bucket GCS).
- Testar a seleção de provider em `criar_dependencias_reais` exigiu `patch()` nos MÓDULOS de
  origem (`ingestion.indexing.qdrant_indexer.QdrantIndexer`,
  `ingestion.embedding.hybrid_embedder.FastEmbedHybridEmbedder`), não no módulo que os importa —
  os imports lazy (`from X import Y` dentro da função) exigem esse padrão para o mock ser
  observado no momento da chamada.

### Communication

- O usuário interrompeu o `/build` desta feature no meio para pedir verificação de por que o
  frontend (`FRONTEND_PREMIUM_GOOGLE_AUTH`, shipado horas antes na mesma sessão) ainda não estava
  online — resposta correta foi registrar o pedido e continuar até o ponto de parada natural
  (fim do `/build`), como já visto antes nesta sessão.
