## Summary

Primeira feature do blueprint: raspa a legislação compilada do Planalto, estrutura em árvore AST (Lei→Título→Capítulo→Artigo→Parágrafo→Inciso→Alínea), gera chunks parent-child com metadados de vigência e indexa via embedding híbrido (BGE-M3 denso + BM25 esparso) no Qdrant. O código foi construído e testado (com fakes) em 2026-07-22, mas o ship ficou pendente por 2 dias porque as credenciais reais (`GCP_PROJECT_ID`, `GCS_BUCKET_NAME`, `QDRANT_URL`, `QDRANT_API_KEY`) só foram provisionadas em 2026-07-24, durante uma auditoria completa do projeto que também resolveu o CI/CD e a política de onde credenciais reais devem viver (GitHub Secrets, nunca `.env` local).

## Lessons Learned

### Process

- Shipar com um critério de sucesso ainda não verificado (busca híbrida real) é aceitável quando a lacuna é documentada explicitamente e tem um caminho claro para fechar — o precedente já foi estabelecido pela feature `ORQUESTRACAO_MULTIAGENTE` (shipada com nós fake por falta de `langgraph`) e reforçado por `INGESTAO_TCU_E_ETL_AIRFLOW` (DAG nunca executada). O padrão do projeto é: nunca fingir que algo bloqueado funciona, mas também não travar todo o progresso esperando o ambiente ideal.
- Credenciais reais (GCP/Qdrant) resolvidas fora do ciclo de código original (numa sessão de auditoria 2 dias depois) mostram o valor de manter o `BUILD_REPORT`/`CLAUDE.md` como fonte de verdade viva — a lista de blockers desatualizada foi pega e corrigida antes do ship, evitando arquivar um documento que diria "credenciais pendentes" quando já não era mais verdade.

### Technical

- **Nunca rodar infraestrutura real localmente, mesmo com credenciais em mãos.** A política adotada nesta sessão (infra real só via GCP/CI, `.env` local só para testes com fakes) significa que ter `QDRANT_API_KEY` no GitHub Secrets não é suficiente para "destravar" a execução E2E — ela só roda de fato quando `dags/ingestao_legal_dag.py` (ou um workflow de CI equivalente) disparar de dentro do GCP. Uma lição que só ficou clara numa feature *depois* desta, mas que se aplica retroativamente ao critério de sucesso pendente aqui.

### Communication

- O usuário corrigiu diretamente a suposição de que "ter credencial = pode rodar local" — vale sempre confirmar onde a execução real deve acontecer antes de sugerir comandos que tocam infraestrutura de produção.

## Recommendations for Future Work

| Area | Recommendation |
|------|----------------|
| Verificação E2E da busca híbrida | Só fecha quando `dags/ingestao_legal_dag.py` rodar de verdade num Cloud Composer (ou workflow de CI equivalente) — não é um blocker de código, é uma decisão de infraestrutura pendente |
| Terceira fonte de ingestão | `PlanaltoScraper` e `TCUScraper` já provam a extensibilidade de `LegalSource` para HTML e PDF — próxima fonte (DOU, RFB/COSIT) deve seguir o mesmo padrão |
| Schema PostgreSQL (seção 7) | Ainda não iniciado — quando entrar, decidir se `Chunk`/`Lei` precisam de algum cache/índice relacional além do Qdrant |
