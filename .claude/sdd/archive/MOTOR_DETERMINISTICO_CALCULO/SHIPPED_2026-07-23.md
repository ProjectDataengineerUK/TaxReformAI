## Summary

Motor Python puro (sem LLM, sem I/O externo) que calcula CBS, IBS, IS e Split Payment para qualquer ano da transição tributária brasileira (2026-2033). Em vez de aceitar alíquotas como parâmetro livre ou hardcodar estimativas de mercado, o motor separa a matemática do cálculo de uma fonte de alíquotas (`TabelaAliquotas`) que só afirma valores realmente confirmados em lei — hoje, apenas a fase de teste 2026 (CBS 0,9% + IBS 0,1%). Para qualquer outra fase, o motor recusa explicitamente o cálculo em vez de simular com um número não verificável, preservando a garantia de auditabilidade que é a proposta de valor central do TaxReform AI (`contexto.md`, seção 1.1).

## Lessons Learned

### Process

- Pesquisar fontes reais (TCU) *antes* de fechar o escopo do brainstorm mudou a decisão de arquitetura de forma fundamental — sem essa pesquisa, o motor teria sido projetado para hardcodar estimativas de mercado como se fossem alíquota oficial, o que teria comprometido a garantia de auditabilidade do produto assim que fosse usado de verdade.
- Reaproveitar o padrão arquitetural já validado na feature anterior (`Protocol` + implementação seed/fake, mesmo estilo de exceção informativa) acelerou o design — a segunda feature levou 2 dias contra o ciclo mais longo da primeira, mesmo com uma sessão de pesquisa externa no meio.

### Technical

- Um teste de arredondamento com números "aleatórios" pode passar mesmo sem provar nada — só um valor que caia exatamente num limite de metade (`X,XX5`) diferencia `ROUND_HALF_UP` do `ROUND_HALF_EVEN` padrão do Python. Vale sempre construir o caso de teste a partir do comportamento que se quer provar, não só rodar a função com um número qualquer.
- Separar "matemática do cálculo" de "fonte de dados legais" (via `Protocol`) é um padrão que se repete bem neste domínio — a mesma ideia usada para `RawStorage`/`LegalSource` (ingestão) se aplicou diretamente para `TabelaAliquotas` (motor de cálculo), sugerindo que é um padrão arquitetural do projeto, não um acidente isolado.

### Communication

- Confirmar explicitamente com o usuário se "sem verificação externa" ainda fazia sentido depois de descobrir a complexidade real da alíquota de referência (78 páginas de metodologia do TCU) evitou que o motor fosse construído com um escopo que o próprio usuário não teria aceitado depois de ver os fatos.

### Tools & Libraries

- `curl` + `Read` (para PDFs) foi suficiente para verificar fontes oficiais reais sem precisar de nenhuma biblioteca adicional — importante quando a alternativa (aceitar um número de uma página que não bateu com a fonte primária) teria introduzido um dado potencialmente incorreto no produto.

## Recommendations for Future Work

| Area | Recommendation |
|------|----------------|
| `TabelaAliquotas` para 2027+ | Próxima feature natural: ingerir as Resoluções do Senado/TCU (fonte nova, identificada nesta feature) e trocar `TabelaAliquotasSeed` por uma implementação real — o motor já está pronto para receber isso sem refatoração |
| Integração com o pipeline de ingestão | `motor_calculo` e `ingestion/` continuam desacoplados de propósito; ao integrá-los, considerar se `fonte_legal` da `RegraFiscal` deveria referenciar um `Chunk` real do Qdrant, fechando o ciclo de auditabilidade ponta a ponta |
| Transição gradual 2029-2032 | Quando a fonte SPED/IBPT for mapeada, decidir se a granularidade da `RegraFiscal` nessa fase precisa ser por UF/município, não só por fase — a estrutura atual (`FaseTransicao` como Enum) pode precisar de um campo adicional |
