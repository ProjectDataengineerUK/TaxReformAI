## Summary

Conecta Claude via Vertex AI de verdade e reescreve os 4 nós fake da orquestração multi-agente
(`classificador`, `pesquisador_legal`, `extrator_regras`, `sintetizador`) para chamadas reais,
fundindo as posições 4 e 5 do roadmap por instrução explícita do usuário ("ja pode entregar
tudo"). `POST /v1/tax/query` deixa de devolver um parecer sintético hardcoded e passa a citar
legislação real recuperada do Qdrant, classificar a intenção da consulta via Claude Haiku, e
sintetizar a resposta via Claude Sonnet — com um guardrail que rejeita qualquer parecer que não
reproduza literalmente os valores calculados. `deterministico.py` (motor de cálculo puro)
permanece intocado. Endpoint `global` do `AnthropicVertex` (recomendação oficial da Anthropic,
sem premium de preço) elimina o que parecia ser um conflito de região com `southamerica-east1`.
Verificada em três camadas de infraestrutura real (Terraform, deploy.yml, Cloud Logging) e por
uma revisão de segurança dedicada que encontrou e corrigiu 2 achados críticos e 2 altos antes do
ship. O único item que não fechou 100% é uma ação externa do usuário (quota do Vertex AI no
Console do GCP), não um bug do código.

## Lessons Learned

### Process

- Rodar a revisão de segurança **antes** de disparar a verificação real de infraestrutura (não depois) foi a ordem certa: os achados dela (guardrail mais forte, PII mais robusta) já estavam no código quando o `deploy.yml` real rodou, evitando reverificar duas vezes.
- Quando um dispatch real falha de um jeito que não bate com nenhuma hipótese óbvia (503 puro, sem corpo JSON), vale mais criar um workflow de diagnóstico DESCARTÁVEL e barato (só leitura de logs) do que tentar de novo às cegas gastando outro ciclo real de build+deploy+LLM.

### Technical

- `fastembed` baixa o modelo ONNX (`multilingual-e5-large`, ~560M parâmetros) de verdade na primeira chamada real — peso que nenhum Cloud Run deste projeto precisou suportar antes, porque `pesquisador_legal` era fake até esta feature. O uso de memória observado escalou quase exatamente até o teto configurado em AMBAS as tentativas (529MB/512Mi, depois 2065MB/2Gi) — sinal de que o processo consome o que está disponível, não um valor fixo; só uma folga generosa (4Gi) resolveu de verdade.
- `gcloud logging read` com `--order=asc` e `--limit=200` devolve as entradas MAIS ANTIGAS dentro da janela de freshness, não as mais recentes — armadilha real que custou uma iteração extra do workflow de diagnóstico.
- Projetos GCP novos podem ter quota zero/mínima para modelos parceiros específicos no Vertex AI Model Garden (aqui, Claude Haiku 4.5) mesmo com a API habilitada e o IAM concedido corretamente — isso só aparece na PRIMEIRA chamada real, nunca em teste com fake.

### Communication

- A pergunta explícita ("prosseguir com mais um deploy real, ou investigar mais primeiro?") depois do 2º fracasso evitou queimar um 3º ciclo de deploy+LLM sem evidência nova — a resposta do usuário confirmou a preferência por investigar antes de tentar de novo.

### Tools & Libraries

- `pip install --target=/tmp/pkg` (em vez de `venv`, que falhou por falta de `python3-venv`) foi a forma mais rápida de validar a forma real da API do `anthropic[vertex]` e do `fastembed` neste sandbox sem tocar no Python do sistema (PEP 668).

## Recommendations for Future Work

| Area | Recommendation |
|------|----------------|
| Custo/latência de cold start | Considerar baixar o modelo `multilingual-e5-large` no BUILD da imagem Docker (`api/Dockerfile`), não em runtime — evita o download não-autenticado do HuggingFace Hub (sujeito a rate limit) em toda nova instância do Cloud Run |
| Rate limiting | `/v1/tax/query` é a primeira feature com custo real por token e ainda não tem cap de tamanho de payload nem rate limiting — gap já conhecido do projeto (mesma recomendação de `API_EMPRESA_SKUS`), mas agora com custo de LLM em jogo, não só de banco |
| `orquestracao/grafo.py` (LangGraph) | Ainda não executável neste sandbox (`langgraph` ausente) — a versão via `functools.partial` foi só revisão de código, nunca testada de fato |
| Quota do Vertex AI | Documentar no runbook do projeto o processo de solicitar aumento de quota, já que qualquer novo ambiente/projeto GCP provavelmente vai precisar do mesmo passo |
